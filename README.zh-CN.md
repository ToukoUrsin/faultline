# Faultline：让网络故障变得可解释

**断开一条链路，看清之后发生的一切。**

Faultline 是一个以 MoonBit 为核心、编译为 WebAssembly 的确定性分组网络实验室。它将「网络坏了」拆解为可检查的事件：哪个分组正在传输、哪个队列已满、路由在哪里改变、没有该故障时会发生什么。

[在线演示](https://toukoursin.github.io/faultline/) · [源码仓库](https://github.com/ToukoUrsin/faultline)

## 运行与验证

需要 Node.js 22 或更新版本，无 npm 依赖，无账号、密钥或外部服务。

```sh
npm start
# 浏览器打开 http://127.0.0.1:8777
```

仓库附带真实编译的 `web/assets/faultline.wasm`。如需修改核心，请安装 [MoonBit 官方工具链](https://www.moonbitlang.com/download)，然后执行：

```sh
npm test
npm run build
```

开发使用 moon 0.1.20260920。测试包括 15 项 MoonBit 测试，以及对真实 WASM 数值接口的集成验证。`engine` 是不依赖浏览器的可复用包；`bridge` 提供数值接口。WASM 模块没有任何宿主导入，不存在 JavaScript 仿真替代实现。

## 三个可复现的观察

- 默认桥接链路在 52 ms 失效，12 个分组中 9 个送达，3 个在途丢失；健康网络对照组全部送达。选择 P03 可查看 16、34、52 ms 的事件链。
- 瞬时突发场景中，12 个分组同时进入容量为 3 的队列，9 个立即因队列满被丢弃。拓扑连通不代表负载可承受。
- 故障时间图表调用 MoonBit 进行 25 次独立仿真。故障更早发生，有时反而让更多分组送达，因为新路由会在分组进入故障链路前避开它。每一根柱子都可以点击复现实验。

最小割分析独立枚举原始拓扑中所有包含一条或两条链路的包含极小故障集合。默认网络没有单链路割，有四组双链路割；按钮可以直接应用计算得到的第一组割。连通性与分组丢失不是同一指标。

## MoonBit 的实质工作

输入边界验证、Dijkstra 最短路径、稳定离散事件调度、双向独立 FIFO 发送队列、队满丢弃、永久故障边界、跳数预算、逐包事件轨迹、延迟统计、故障时间扫描、BFS 连通性、最小割枚举都由 MoonBit 实现。JavaScript 只负责交互、SVG 绘制、时间播放和文件导入导出。导入文件后重新计算，不信任文件附带的结果。

## 明确边界

这是用于教学和工程推理的小型模型，不是生产网络预测器。没有 TCP、重传、拥塞控制、真实抓包或分布式路由收敛。路由立即知道链路故障。故障发生时，等待和在途分组都被丢弃；恰好与到达同时发生的故障优先。动画将串行发送时间与传播时间合并为一段。只有成功送达分组参与延迟统计。完整语义见 [MODEL.md](docs/MODEL.md)。
